## Critical

### C-1: The entire DB-backed test layer and `scripts/test-rls.sql` run nowhere in CI

**Files:** `.github/workflows/ci.yml:45-46`, `package.json:24`,
`vitest.config.ts`, `src/lib/presbytery.test.ts:53-56` (the `skipIf` pattern,
repeated in 30 files)

1. **`npm test` is `vitest run`** (`package.json:24`) — no `--no-file-parallelism`,
   no env loading. The requirement exists *only* in work-log prose (14
   occurrences across three work-logs). The same work-log records what the
   default-parallel run actually does: *"Flaky: 4–7 suite-level teardown
   failures per run."*
2. **CI's `Unit tests` step sets no `DATABASE_URL`.** `ci.yml:33` sets one for
   the *build* step only. So all 30 DB-gated suites `describe.skipIf` out. The
   ~30 files that prove RLS isolation, the freeze triggers, composite-key
   enforcement, the permission resolver, `withOrgContext()`'s check-before-
   `set_config` ordering, and every about-org affiliation rule **never execute
   in CI.**
3. **`scripts/test-rls.sql` runs in no workflow at all.**

presby's stated invariants are verified only when an agent hand-assembles
`npx dotenv -e .env.local -- npx vitest run --no-file-parallelism` plus a
separate `psql -f scripts/test-rls.sql`, against a *shared* branch. CI is
green on a suite stripped of exactly the tests that matter most.

**This is not a hard problem in this repo.** `.github/workflows/e2e.yml:56-95`
already creates an ephemeral Neon branch per run and exports a live
`DATABASE_URL` to the job.

**Proposed fix:**
1. `package.json`: `"test": "vitest run --no-file-parallelism"`, or
   `test.fileParallelism: false` in `vitest.config.ts` with a header comment.
2. Add a `db-tests` job to `ci.yml` modelled on `e2e.yml`'s Neon-branch step:
   create branch → `npm run db:migrate` → `psql -f scripts/seed-dev.sql` →
   `npx vitest run --no-file-parallelism` → `psql -v ON_ERROR_STOP=1 -f
   scripts/test-rls.sql` → delete branch.
3. Until (2) lands, `/pre-push` must fail — not warn — if the DB-backed run and
   `test-rls.sql` were not executed in the session.

## Summary

presby's first real code review finds a codebase whose *stated* conventions are
unusually well-followed and whose *mechanical* enforcement has not kept pace
with how much the code has changed shape since it was scaffolded. The three
criticals share one root cause: each guard was written against the starter's
shape, presby changed shape underneath it, and nothing said so — the project's
invariant-tripwire discipline, applied to the tripwires themselves. The hard
things are in good condition; where a document and the code disagreed, the code
was right. Two items have survived three cycles across two repositories and
both are three-line fixes; the second was recorded as fixed on a spot check —
the fix for that is the same as for C-2: write the check as a script, not a
paragraph.

*Cross-review boundaries: N-6's trigger remediation belongs to the security
review's pipeline; N-8 to deployment-engineer; N-1/M-5 to the documentation
review. No new DECISION proposed; if R16-1–5 are accepted as a package, that is
a decision worth numbering.*
