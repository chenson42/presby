## 0.31.0 — 2026-10-05

### A new organization can be placed under its presbytery or synod when it is created

**Background:** The platform has long been able to record that a congregation belongs to a presbytery, or a presbytery to a synod, but the screen where an operator creates an organization never offered a way to say so. Every organization created through the product arrived with no parent council, and the relationship had to be written directly into the database afterwards. For a presbytery to be onboarded with its congregations, that gap had to close.

**Changes:**
- When creating an organization, the operator can now choose its parent council from a list that only ever offers the right kind of parent for the type being created: a presbytery for a congregation or new worshiping community, a synod for a presbytery, the General Assembly for a synod. The kind of relationship is worked out from that pairing rather than typed. An optional minute reference can be recorded with it.
- Choosing no parent remains a normal, legitimate choice: a presbytery with no synod above it is a valid root, and the form never implies otherwise. The General Assembly has no parent field at all.
- An organization's page now shows its council affiliation: the parent's name, linked to the parent's own page, the kind of relationship, since when, and the minute reference if one was recorded. An organization with no parent says so plainly.
- The server's own checks are unchanged and still apply regardless of what the form offers: an impossible pairing or a parent that no longer exists is refused with the existing plain message, never saved.
