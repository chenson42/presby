## 0.23.0 — 2026-08-28

### Feature: Custom leadership and committee pages

**Value:** The public staff directory could only show one flat "everyone" list. A congregation building a real website wants more control — a curated leadership page with a hand-picked, ordered group of people, and separate pages for each committee. This release makes that possible without any new code: a website author can now request exactly the subset of public staff, officers, or committee members they want, in whatever order the congregation prefers.

**What's New:**
- A website page can now request a filtered view of the public directory — by department, by office, or a hand-picked "leadership" subset ordered however the congregation prefers.
- Committee membership can now be listed publicly too, the same opt-in way staff and officer listings already work — each committee member is added one at a time, off by default, with the same plain confirmation dialog explaining what going public means.
- A public visitor can now see either a single committee's roster or a directory of every committee that has opted members in, grouped by committee name.
- Admins managing staff, officers, and committees can now set a display order for anyone who's opted into public listing, so a leadership page shows people in the order the congregation wants rather than alphabetically.

**Permissions**

| Feature key | Required for |
|-------------|--------------|
| `groups.manage` | Marking a committee member's listing public or private, and setting display order |

**Scope:** Ships behind a new `sites.public_committee_directory` flag, seeded off, independent of the existing staff/officer directory flag. Photo display remains unwired for all three (staff, officers, committees) — tracked as a priority follow-up.

## 0.23.1 — 2026-08-30

### Security: Automated scan for secrets and private information before every push

**Background:** This project's source code is now public. An automated check was added that scans the entire codebase for anything that looks like a password, an API key, or private contact information, and must pass before any change can be published going forward.

**Changes:**
- Every future change is automatically checked for accidentally-included secrets and personal information before it can be published.
- Running this check once against everything already in the project found and corrected two things: an old test password that had been written into a planning document, and a real address and phone number that had been entered while testing a feature. Both have been removed from the current version of the project.

## 0.23.2 — 2026-09-24

### Corrected how the home page describes Presbyterian church government

**Background:** The public home page described church government in a way that read like a corporate reporting chain rather than Presbyterian polity. It said that every session "answers upward, through presbytery and synod, to the General Assembly," and that the courts of the church connect each level "to the ones above it."

That is not how the Book of Order describes it, and it contradicts the way this platform is actually built: records move between councils deliberately, by publication, and a higher council does not gain access to a congregation's records simply by sitting above it.

**Changes:**
- The home page now describes session, presbytery, synod and General Assembly as distinct councils, each with its own responsibilities, whose work and records connect — and says that records move between councils deliberately rather than by inheritance.
- No functional change. Wording only, on the public home page.

## 0.23.3 — 2026-09-24

### Web framework updated to close two critical image-handling vulnerabilities

**Background:** The framework the site runs on published two critical security advisories affecting the version in use. One of them concerned the component that resizes and serves images, which the public congregation sites use. The pre-publish check caught the advisories and held the previous release back until they were addressed.

**Changes:**
- The web framework and its image-processing library were updated to versions that close both advisories, along with two smaller advisories in development tooling.
- No functional change. Pages, images and sign-in behave exactly as before.
