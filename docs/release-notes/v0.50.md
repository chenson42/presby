## 0.50.1 — 2026-10-28

### Fix: a presbytery set up before automatic setup existed can now be sent a founding-administrator invitation

**Value:** An administrator can now send the first invitation to a presbytery that was created before the platform set up an organization's basics automatically. Before, that organization could not be sent one, and the page said it was missing its baseline setup.

#### What's New

- **The invitation can be sent.** A presbytery set up before automatic setup existed couldn't be sent a founding-administrator invitation; it now can. Applied directly to production on 2026-10-28.
- **What was added.** The same two things every organization gets when it is created today: its "Active Membership" group and the ordinary "Member" role, which lets members see the directory and, where it is turned on, the events calendar. Nothing else about the organization changed, and no other organization in production was touched.

**Notes for the operator:** the fix is migration `0082`, already applied to production (after a snapshot) and to `development` on 2026-10-28, so there is nothing to apply at deploy. A fresh environment migrates cleanly through it; the file was corrected before release so it does so. The deploy itself carries no code change. If an organization ever has membership records (current or past) but no "Active Membership" group, the migration stops rather than guess; production had none. See `docs/deployment.md`, "Organization baseline backfill (0082)".

**Technical:** migration `0082_presby_backfill_org_baseline.sql` (idx 82); data-only, idempotent, adds nothing to an organization that already holds a `member` role. Regression test `src/lib/db/domain/org-baseline-backfill.db.test.ts`. Work-log `2026-10-28-org-baseline-backfill`. Its two guards (the "roster missing" check now raises only when an organization needs the group; the membership stop-block refuses on any membership row) were corrected in place before release, under DECISION-298 (in-place correction of an applied migration). No what's-new post.

## 0.50.0 — 2026-10-28

### Feature: help on the website

**Value:** People who sign in, church administrators and congregations thinking about PresbyPortal had nowhere to read how it works. Most support questions (signing in, a lost code, a missing page or button, the first day as an administrator) now have a plain-language page anyone can read without signing in.

#### What's New

**Help is now on the website.** PresbyPortal has a help site at presbyportal.org/help, and anyone can read it without signing in. It has plain-language guides for people who sign in, covering signing in, using your code, your account, why a page or button might be missing, and getting help. For church administrators it covers your first day, turning features on and off, adding people, officers and the Session, roles, events and the calendar, your congregation's website, and inviting people to sign in. There is also a short list of things PresbyPortal does not do yet, which is not a promise and has no date. You'll find a Help link on the home page, in the account menu, and on the sign-in, two-factor and no-access pages. Each guide says which release it was last checked against. The guides describe what the app does today, including where it does not yet do what you might expect: a new congregation's first administrator cannot yet add events or set the congregation's colours without asking the PresbyPortal team, and the guides say so. There is no contact form yet, so for now they point you to the person who invited you. The help pages are not yet listed by search engines.

- Guides for accepting an invitation, setting up two-factor sign-in and saving your recovery codes, and who is asked for a code are also there, and the invitation page now has a "Help with this page" link.
- **A privacy policy** is at presbyportal.org/help/privacy-policy: what PresbyPortal keeps about you, what a congregation keeps, who helps us run it, how long things are kept, and how to ask about your information.

#### New Routes

- `GET /help` — the help index, grouped by audience
- `GET /help/<page>` — one guide (twenty-one published)
- `GET /help/planned` and `GET /help/planned/<item>` — the five things PresbyPortal does not do yet
