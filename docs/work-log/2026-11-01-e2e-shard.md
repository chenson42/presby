## Why

The `playwright (dev lane)` job runs every spec (839 on PR #73) serially on one worker against `next dev` and a remote Neon branch. Test time alone was ~67 minutes, plus ~8 minutes of setup. It hit the 75-minute job limit with no failing spec on PR #73 and on the PR #70 merge-to-main run. The PR #72 merge run passed at 73m 37s. PR #73 raised the limit to 120 minutes as a stopgap and added the TODO line this work closes.

The operator asked for the dev lane to be sharded (2026-11-01). They also asked whether the full suite belongs in per-PR CI at all or should run nightly. That question is open; see the end of this file.

## Phase 4 — Implementation (orchestrator)

- `e2e.yml`: the matrix is now `include` rows: four `dev` shards (`--shard=i/4`) and the `prod` lane. Each row gets its own ephemeral branch (`e2e-<lane>-<run>-<attempt>-s<shard>`) and its own trace artifact name (upload-artifact v4 refuses duplicates). Check names are now `playwright (dev lane i/4)` and `playwright (prod lane)`; main has no branch protection, so no required check is renamed. The per-job limit is 45 minutes.
- `playwright.config.ts` is unchanged: still `workers: 1` and `fullyParallel: false`, so Playwright shards by spec file and each shard is the same serial run over a quarter of the files.
- `--list` preview on main (830 tests): shards of 217 / 211 / 202 / 200 tests, in 23 / 34 / 20 / 23 files.
- `docs/testing.md`: the shape paragraph names the shards and the new rule that a spec file must not depend on state another file leaves behind. A stale sentence saying the prod lane is a second step of the same job is corrected.

**Cost.** Wall time per PR drops from ~75 to ~35 minutes (the slowest shard; first run 34m). Runner minutes rise by three extra setups (~25 min); Actions minutes are free on a public repository. Neon gets three more concurrent 2-CU branches per run: peak CI branches go from 7 to 10. Total compute-hours are about the same, plus ~3 × 8 minutes of setup.

**Risk.** A spec file that silently relied on an earlier file's leftovers fails once it lands in a different shard. The PR's own run is the test of that.
