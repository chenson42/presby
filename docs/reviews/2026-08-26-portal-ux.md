# Portal UX Review — 2026-08-26

Operator-requested ("after this i think it would be a good time to do a UX review of the
portal. for usability, UX standards, consistency, moderness"), run as a live-browser pass
(Playwright against the running dev server, real fpcw data, all portal flags on) at 1280px
and 390px across every portal surface: home, directory (members/households/parishes +
detail pages), admin hub, members (list/wizard/edit/sensitive), officers, groups, roles
(+ create form), branding, features, tickets, feedback. Measured against
`docs/ui-standards.md` and the DECISION-104/105 visual direction. Every finding was
verified in a real browser (screenshot + DOM/computed-style confirmation), not inferred
from source. Screenshots archived in the session scratchpad at review time.

## High severity

- **H1 — Sensitive-info page's `Note type`/`Visibility`/`Source` selects have `appearance-none` but no chevron** — they read as static text, so a user cannot discover that a pastoral note's visibility can be raised to `clergy_only` — the exact tiered-privacy control the feature exists to expose. Fix: standard `relative` + `ChevronDown` wrapper (`ui-standards.md` § Select & Combobox).
- **H2 — Edit-person's "Roll action" select renders native browser chrome** (`appearance: auto`, no chevron) directly below a correctly-styled household select on the same page — an un-retrofitted instance of the select-drift class already fixed elsewhere today.
- **H3 — No unsaved-changes guard on any admin form, confirmed live** — dirtied a field on `/admin/members/[id]/edit` and `/admin/branding`, clicked "Back to portal": silent navigation, changes lost, no dialog. `ui-standards.md`'s own documented `isDirty` + `AlertDialog` pattern is used nowhere. Highest-cost on the ~16-field edit-person form.
- **H4 — Directory Parishes tab shows two dead-end cards** — Members and Households cards drill down; the parish district cards have no `href` at all (verified), yet look identically clickable. Wire them up or visually demote them.

## Medium severity

- **M1 — `/admin/roles` and `/admin/officers` tables clip actions off-screen at 390px with zero scroll affordance** — "Edit" (roles) and the tail of "End term" (officers) are invisible unless the user guesses to swipe; the wrapper genuinely scrolls but shows no cue. Add a fade/affordance, or collapse to cards like the Members list.
- **M2 — `/admin/members/[id]/edit` crams profile editing, roll-action recording, and the sensitive-info link into one undifferentiated scroll** separated by a bare `<hr>` — the highest-traffic admin form, visually predating the DECISION-104/105 card language. Wrap the concerns in distinct `bg-card` panels or tabs.
- **M3 — The sensitive-info page is the plainest page in the app despite holding tier-3 data** — nothing signals "restricted"; borrow the existing lock-badge language for a "Tier 3 — restricted" indicator.
- **M4 — Racial/ethnic checklist has 9 options and no filter input**, violating `ui-standards.md` § Multi-select's ~6-option threshold.
- **M5 — Three different empty-state treatments coexist** — groups (dashed card, spec-perfect), directory zero-result search (best in app), pastoral notes (bare muted text). Standardize on the dashed-card pattern.
- **M6 — "Groups" (home) and "Branding" (hub) share the identical grid glyph** in their icon badges — give Branding a paint/swatch icon.

## Low severity

- **L1** — Directory member/household cards are real links but carry no chevron/hover-lift affordance, unlike the tiles (DECISION-104's own pattern).
- **L2** — Branding's logo file input is unstyled native OS chrome next to custom-styled inputs.
- **L3** — Required fields aren't marked; requiredness must be inferred from the absence of "(optional)".
- **L4** — Feedback page is write-only with no history/status of past submissions, despite promising review.
- **L5** — Mobile nav expands in-flow (pushing content down) rather than an overlay drawer — the oldest-feeling interaction left in the portal.
- **L6** — Tickets' permission-denied copy is excellent writing but visually bare; the lock-badge treatment could be reused.

## What's working (protect, don't touch)

Home + admin hub fully deliver the DECISION-104/105 language and survive 390px cleanly;
the 6-step add-a-person wizard is well-built at both widths; the directory's zero-result
empty state is the house-best example; all checked touch targets ≥44×44px; radios are
properly label-wrapped; Branding's responsive layout + live light/dark previews are a
strong constrained-form example.

## Top 5 highest-leverage (operator to pick)

1. H3 — unsaved-changes guard on edit-person + branding (confirmed data-loss risk).
2. H1 — the chevron-less selects on the sensitive-info page (hides a real capability).
3. M2 — visual structure for edit-person (highest-traffic, least organized).
4. M1 — mobile scroll affordance for the roles/officers tables.
5. H4 — resolve the Parishes dead-end cards.
