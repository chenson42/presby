## 0.23.0 — 2026-08-28

### Feature: Custom leadership and committee pages

**Value:** The public staff directory could only show one flat "everyone" list. A congregation building a real website wants more control — a curated leadership page with a hand-picked, ordered group of people, and separate pages for each committee. This release makes that possible without any new code: a website author can now request exactly the subset of public staff, officers, or committee members they want, in whatever order the congregation prefers.

**What's New:**
- A website page can now request a filtered view of the public directory — by department, by office, or a hand-picked "leadership" subset ordered however the congregation prefers.
- Committee membership can now be listed publicly too, the same opt-in way staff and officer listings already work — each committee member is added one at a time, off by default, with the same plain confirmation dialog explaining what going public means.
- A public visitor can now see either a single committee's roster or a directory of every committee that has opted members in, grouped by committee name.
- Admins managing staff, officers, and committees can now set a display order for anyone who's opted into public listing, so a leadership page shows people in the order the congregation wants rather than alphabetically.

**Permissions**

| Feature key | Required for |
|-------------|--------------|
| `groups.manage` | Marking a committee member's listing public or private, and setting display order |

**Scope:** Ships behind a new `sites.public_committee_directory` flag, seeded off, independent of the existing staff/officer directory flag. Photo display remains unwired for all three (staff, officers, committees) — tracked as a priority follow-up.
