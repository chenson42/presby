## 0.8.2 — 2026-08-18

### Fix: The E2E Suite Owns Its Test Users

**Background:** `npm run test:e2e` exited **0** after running 6 of 48 specs. Authenticated specs needed a signed-in session; the credentials came from six `SEED_*` environment variables; when those were unset `globalSetup` logged three "Skipping" lines, every authenticated spec called `test.skip()` on the same condition, and Playwright counted the skips as not-failures. A green suite that ran 12% of itself.

That matters here more than in most repos. CLAUDE.md's Phase 5 gate requires, for any auth-touching change, an e2e run against a real dev server *including an MFA-enrolled user*, and states that a deferred check is `BLOCKED`, never `PASS`. A suite that silently shrinks lets that gate be satisfied by a run in which the auth specs never executed. The v0.7.0 notes cite "48/48" for a command that today produced 6.

**Changes:**

- **Fixture users are hardcoded** in `e2e/support/users.ts` and provisioned into the database by `globalSetup` on every run (`e2e/support/seed-users.ts`, idempotent). There is no configuration left to omit, so there is nothing to skip on.
- **Every `test.skip()` credential guard is deleted** across ten spec files, along with the `HAVE_*` constants and five copies of the same `storageStatePath()` helper. The pattern cannot grow back by accident.
- **The dividing line is explicit** (DECISION-032): test users are fixture data and the suite owns them; roles and features are application catalog data and stay with `npm run db:seed`. The seeder binds to roles that must already exist and fails loudly naming the fix if they do not.
- **A committed test password is kept harmless** by construction: every fixture email ends in `@example.invalid` (a reserved TLD that can never resolve), and the seeder refuses to provision any user whose address does not — so it cannot touch a real account even pointed at the wrong database.
- **`.github/workflows/e2e.yml`** no longer generates six per-run credentials.

**Two defects surfaced by actually running the specs:**

- **A rate-limited sign-in is indistinguishable from a wrong password.** `src/auth.ts` caps credentials sign-in at 5/min per `ip:email` and returns `null` when exceeded — before the password check — so the UI shows "Wrong email or password" while `failed_login_attempts` stays at 0. Six specs failed this way with an error that actively misdescribed the cause. `playwright.config.ts` now sets `RATE_LIMIT_DISABLED` for a server it starts, and `globalSetup` refuses to run without it, naming the symptom.
- **Both 2FA pages crash when `AUTH_TOTP_ENCRYPTION_KEY` is unset** — an unhandled runtime error, where Turnstile no-ops and Resend falls back to stdout. Tracked in `docs/TODO.md` for the 2FA work.

**Verified:** 48 passed, 0 failed, 0 skipped, against a real dev server, with no `SEED_*` variables set — the exact configuration that previously yielded 6 passed / 42 skipped.

## 0.8.1 — 2026-08-18

### Polish: Identity Pass

**Background:** `chenson42/presby` was created on 2026-08-18 — private now, open source once it is public-ready. Everything a visitor or a member read first still said *Claude Code Starter*, and some of it was not documentation: it was application text going out in emails and burned into TOTP enrolments.

**Changes:**

- **`README.md` rewritten.** It described a fork-and-go starter and told you to clone a different repository. It now describes presby, leads with the no-real-data invariant, explains the four polity constraints that shape the schema, states plainly that there is no church-facing UI yet, and documents the four connection strings and why the difference matters.
- **`package.json`** — `presby`, with a real description, a `repository` field, and `license: MIT` (the LICENSE file has always existed; the manifest never declared it). `private: true` stays: it blocks an accidental `npm publish` and is unrelated to repository visibility.
- **Application text** — landing page (plus a new pre-release line so no one mistakes this for a live system), the global nav brand on every authenticated page, the admin shell back link, and the default email From name.
- **TOTP issuer** is now `presby`. This is the label users see in Google Authenticator or 1Password. It is written into the `otpauth://` URL at enrolment time, so **anyone already enrolled keeps the old label until they re-enrol** — their secret is unaffected. The unit assertion moved with it and got stronger: it checks both places the URL carries the issuer instead of matching a substring.
- **`.env.example` — a functional fix, not cosmetics.** It was missing `PLATFORM_DATABASE_URL`, `MIGRATE_DATABASE_URL`, and `APP_DATABASE_URL`, while `src/lib/db/index.ts` calls `required("PLATFORM_DATABASE_URL")` at startup. A fresh clone following the only setup instructions in the repo could not boot the app. All four database entries now carry the isolation rationale inline, and `DEV_ALLOWED_ORIGINS` is documented.
- **Process layer** — the nine agent definitions in `.claude/agents/` each opened with "You are X for the Claude Code Starter"; they now name presby. Also `eslint.config.mjs`, `docs/ui-standards.md`, and the fork-sync line in `docs/reviews/log.md`.

**Deliberately unchanged:** the `upstream-sync` / `downstream-sync` / `personalize-starter` skills (the canonical starter URL in them is load-bearing), every historical record (release notes, decisions, past work-logs and reviews), and the provenance comments in code that mark the seam between the inherited platform shell and presby's own domain. Renaming those would falsify true statements.

**Still un-run:** `/personalize-starter`. The project has no name yet — `presby` remains a placeholder running through the database role, the SQL functions, and the migration filenames. This pass makes that placeholder *consistent*, which turns the eventual rename into one find-replace.

**Verified:** typecheck · lint · build · 424 unit tests · landing page inspected on a running dev server. The authenticated surfaces (nav, admin shell) were **not** browser-verified — local e2e skipped 42 of its 48 specs because the seed-user env vars are unset on this machine. Both changes there are static text in server components, and the served HTML contains no occurrence of the old name.

## 0.8.0 — 2026-08-18

### Feature: The presby Domain Layer

**Background:** v0.7.0 and everything before it were the platform shell inherited from the starter — auth, roles, flags, audit, email. This release is the first that is *presby*: the church domain, and the isolation model it needs. There is no UI for any of it yet; the read paths exist and nothing surfaces them.

**Schema — 37 tenant tables** across `src/lib/db/domain/` (org, people, roll, officers, groups, authz, privacy, reporting), applied to Neon as migrations `0008`–`0012`:

- **Global person, org-scoped membership.** `people` holds the human; `memberships` carries roll status per organization. Decided on polity, not convenience: ministers of Word and Sacrament are members of the *presbytery* (G-2.0502) while ruling elders are members of the *congregation*, so one person's roll and service routinely sit at different orgs. The model was reversed twice mid-build before landing here (D1).
- **The roll is event-sourced.** `roll_actions` is append-only; an approved action is frozen by trigger and corrected by recording a `void`, never by update. The directory is a view of it, the annual statistical report a projection of it, per capita derives from it.
- **Officer terms, not officer flags.** Ordination is lifelong; service is termed. Session and diaconate rosters *materialize* from `officer_terms` by trigger and reject direct writes — materialized rather than a view because the permission resolver reads `group_memberships`, and a view would be invisible to it (F3).
- **Composite tenant keys.** Every tenant table declares `unique (id, organization_id)` and foreign keys between tenant tables are composite, so a row in org B cannot reference a person in org A (F2).
- **Partial adoption is the norm** (D9). Most congregations will never be tenants; a presbytery's launch-day job is holding records *about* non-tenants. `organizations.platform_status` carries that.

**Isolation — a database property, not an application one:**

- `presby_app` is `NOBYPASSRLS`; every tenant table is `FORCE ROW LEVEL SECURITY`. Without `FORCE`, Postgres exempts the table owner, RLS is silently inert, and every naive test still passes (F1).
- Two connections: `db` (RLS enforced, the app) and `getPlatformDb()` (bypasses RLS, platform pages only). `users.is_platform_admin` decides which *pages* are reachable, never whether a query is filtered.
- `withOrgContext()` verifies membership *before* setting the org GUC — RLS enforces tenancy, not authorization; the policy trusts whatever org id it is handed.
- The app now runs on the RLS-enforced connection by default, and the WebSocket pool (`drizzle-orm/neon-serverless`) is mandatory: neon-http has no session or transaction support, so it cannot carry a transaction-scoped GUC at all (F28). The isolation model dictated the driver.
- `scripts/test-rls.sql` — **36 assertions, and they must run as `presby_app`.** Run as the owner they prove nothing, because `neondb_owner` has `rolbypassrls = t`.

**Authorization:** `presby_effective_permissions(person, org, as_of)` resolves four arms — direct grant, group, administrative commission, session-granted delegation — and returns provenance with each permission, so "why does this person have this?" is answerable. `presby_available_organizations()` backs the org switcher.

**Roll read path:** `presby_roll_as_of`, `presby_roll_counts_as_of`, `presby_roll_changes`, plus `presby_reconcile_current_roll` and `presby_roll_cache_drift`. `memberships.current_roll` is a *cache* and cannot answer historical questions — reports replay through `presby_roll_as_of()`. It also drifts with the passage of time, because future-dated actions take effect on a day with no corresponding write (F29); the daily reconcile in `/api/cron/maintenance` exists for exactly that.

**Officer registers:** `presby_officer_roster(org, office, as_of)` and `presby_officer_history`. A second, non-consecutive term used to rewrite the first term's end date — the derived-group trigger destroyed officer history (F22).

**`/developer` — generated schema reference:** index, per-table pages, per-module ERDs, and `schema.json`. Table and column descriptions live in Postgres `COMMENT ON`, so the documentation cannot drift from the database. Each key invariant is marked `database`, `trigger`, or `paper` — **paper means the schema permits a violation and only review will catch it.**

### Fixes

- **LAN dev assets** — Next blocked `/_next/*` for phone-on-the-same-wifi testing, so the page rendered and never hydrated. `DEV_ALLOWED_ORIGINS` documented.
- **`<details>` on iOS** — a `display` rule on `<summary>` silently breaks native disclosure on iOS Safari. Two of the three bugs in this release were phone-only and invisible to `curl`, `tsc`, and `next build`.
- **ER diagrams** rendered, and table descriptions surfaced while collapsed.
- **OpenGraph metadata** added; the inherited starter title dropped.
- **Stale test guards** — deleted the obsolete neon-http `db.transaction()` guard (moot since the F28 driver switch) and re-pointed the cron-maintenance assertion at the F29 roll reconcile rather than a bare call count.

### Known Gaps

- **No UI for any of the above.** The roll read path is complete and nothing surfaces it.
- `organizations.path` is still `text`, not `ltree`; the ancestry trigger is unwritten.
- Derived groups are not seeded at org creation (F16) — the officer trigger raises until they exist.
- `ADMIN_ROLE` in `src/lib/permissions.ts` is still a wildcard, violating the no-wildcard invariant. Bounded (platform shell only, and the tenant connection cannot bypass RLS) but not removed.
- Photos: `people.photo_key` awaits an object-storage adapter (F13).
- 2 critical `@auth/core` advisories remain open pending the `next-auth` beta.32 upgrade, which needs its own e2e-gated auth pipeline.

### Verification

`npm run typecheck` clean · `next build` clean · 424 unit tests passing · 36 RLS assertions passing as `presby_app` · both tripwires (`check:audit`, `check:sql-date`) clean.
