## 0.12.0 — 2026-08-21

### Feature: Public-site profile data, and a real component library to render it

**Value:** `/site/<slug>` (still flag-gated off) had the plumbing for a congregation's public website but nothing for it to actually say — no address, no service times, no social links, and the shared rendering package (`presby-site-kit`) was a stub that only ever showed a page title and "Content coming soon." This release closes both gaps together, and proves the whole path works with a real end-to-end run rather than tests alone.

#### What's New

- **A congregation's public-site profile** — address, phone, up to five named social links (Facebook, Instagram, X, YouTube, one other), and structured weekly schedules for both service times and office hours (day, start, end, an optional label). Set once by a platform admin at `/admin/organizations/[id]`, read anonymously through the same enumeration-safe function (`presby_published_site()`) that already gates page content — a site that isn't live leaks nothing new.
- **`presby-site-kit` is a real component library now** (v1.0.1, a separate versioned dependency): a hero, a four-up feature grid, a callout band, a service-times list, a staff directory, a values grid, a ministry list, an events list, a sermon-archive link, a donate link, and constrained Markdown prose — plus footer chrome (address, hours, social icons, a "get directions" link) composed automatically from the new profile data. Every piece is independently omittable: a congregation that hasn't set a phone number simply has no phone line, not a blank one.
- **Content is typed data, never executable code.** A content repo authors a page as a list of typed blocks (`{ type: "hero", props: {...} }`); an unrecognized block type is skipped, not rendered, not executed. This was a deliberate call against using real MDX, which lets an author embed arbitrary JavaScript — a private content repo is a lower trust tier than presby's own code, and this keeps every crossing of that boundary data-only. A hand-rolled Markdown renderer (no new dependency) backs the prose block; an adversarial test confirms a `<script>`/`onerror` payload in page content never executes, only ever renders as inert text.
- **Verified for real, not just in tests.** The whole pipeline — a genuine GitHub Actions workflow run, a real signed OIDC token, a live POST to a running dev server, a real render — was exercised twice this release, once to prove the mechanism and once after a real bug fix. It's the first time this architecture has been driven end-to-end by an actual external CI run rather than a simulated one.

| Feature key | Required for |

| `admin.organizations` | Setting a congregation's profile/service-times at `/admin/organizations/[id]` — no new key, reuses the existing admin surface |

#### Also

- **A real bug found by the end-to-end run, not by any unit test**: Postgres serializes a `time` column as `"10:15:00"`, not `"10:15"` — `presby-site-kit`'s first release only matched the shorter form and silently printed the raw value instead of formatting it. Neither side's own test fixtures used the real shape; only running the actual pipeline caught it. Fixed and shipped same-day as `presby-site-kit` v1.0.1.
- **Admin ticket lists no longer overflow.** A long ticket subject blew out the table column on both the platform triage queue and a congregation's own ticket list — `whitespace-nowrap` plus an unclipped max-width let text force the layout wide instead of truncating. Both now truncate with the full subject available on hover.

### Verified

1688 unit/integration tests (up from 1653) · 9 new e2e cases against `/admin/organizations/[id]`'s two new sections, run twice with no flakiness · `presby-site-kit`'s own suite (67 tests across 16 files, a separate repo) · a real GitHub Actions ingest run, twice, against a running local server via a public tunnel · isolation suite re-run clean (99 assertions, 0 failures) after the schema addition · typecheck, lint, build, and all four tripwires green.

One coverage gap was caught and closed mid-pipeline: QA's first pass on the profile-data admin UI failed for missing e2e coverage against the page's own established precedent (the brand-editor's CRUD smoke test); a targeted follow-up closed it and QA re-verified clean.

**Still ahead of a real deploy**, unchanged from v0.11: the `sites.public_render` flag stays off, no real congregation has a provisioned site, `presby-site-kit`'s git-dependency install is unverified against Vercel's actual build sandbox, and `site-<slug>` content-repo visibility (public vs. private) remains an open operational decision.
