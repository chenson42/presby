## 0.47.0 — 2026-10-26

### Feature: job openings

**Value:** A congregation can write its job openings, publish them, and have anyone read them on its own website, instead of sending people a link to a document. This is the first step. People apply by contacting the church; applying online is not part of this release.

#### What's New

- **It is off until someone turns it on.** An administrator switches on "Job openings" under Features for their congregation. No congregation has it on today.
- **Writing an opening.** People who manage job openings can create one with a title, a short summary, a location, the kind of job (full time, part time or intern), optional pay, an optional closing date and a description. The description box has a toolbar and a live preview, and it takes text pasted from Word or Google Docs, keeping headings, bold, italic, links and lists. If you enter an amount of pay you must choose "per hour" or "per year"; nothing is assumed.
- **Publishing and closing.** Publish, Close and Reopen each ask first. A draft can be seen only by staff. A closed opening shows visitors only its title and a note that it is no longer accepting applications. An opening is never deleted: a draft nobody wants is discarded, which closes it. A congregation can have up to 100 published openings at a time. An opening whose closing date has passed closes by itself overnight.
- **Where visitors read them.** The list is at `/careers` and each opening has its own page, on the platform address and on the congregation's own domain. They look like the Give page: the congregation's colours and fonts and a link back to its website, without the website's top menu and footer. Open openings can be found by search engines; closed ones cannot. Whoever maintains the congregation's website can also place the list inside a page, such as an Employment page, with the menu and footer around it; that is a change to the website's own files, not part of this release, and nothing is added to any website by it.
- **Order.** Newest first. Staff can move a published opening up or down.
- **A ready-made Hiring Committee role.** A founding administrator can adopt "Hiring Committee" at Roles and give it to a committee's group, so membership decides who may manage openings. It carries two permissions: managing job openings, and viewing job applications. It works only where the platform's Roles and Administration pages are turned on.

#### Things to know

- **Existing and new founding administrators receive both permissions.** This release adds "manage job openings" and "view job applications" to every founding administrator, those already designated and those designated from now on. The second one reads nothing yet, because applications do not exist yet. When online applying arrives, a founding administrator will be able to read the applications and download resumes. That release is planned to record each resume download in the audit log, so use can be checked afterwards; the record cannot stop it.
- **A website page cannot sit under `/careers/`.** The platform uses addresses like `/careers/office-administrator` for openings, so a website page at one of them is refused when the website is published, with a message naming the page. A page at exactly `/careers` is still allowed and is the one shown there. No website had one when this was checked on 2026-10-25.
- **A pasted link the platform cannot keep is dropped without a message.** Only web addresses (http and https) and email links are kept; the link text stays.
- **Typed text can change meaning.** A star, or a line that starts with a dash, a number and a dot, or a hash mark, is read as formatting. The live preview shows what visitors will see.
- **Closing a published opening saves your unsaved changes first**, so those changes are briefly visible on the page before it closes.
- **Text typed in the first second after pressing Save can be lost**, because the form reloads. Wait for the confirmation.
- **Openings are not yet listed in a website's sitemap**, and they carry no extra markup for Google's job listings.

**For the operator.** This release has a migration, `0071`, and it must be applied to production **before** the code is merged. The steps, in order, are in `docs/deployment.md`, "Careers (0071)": snapshot, re-read the live bundle function (it should have nine keys), count the founding-administrator roles the migration will give the two keys to, check that no website has a page under `/careers/`, apply, and verify against the catalog. Check that the platform flags `org_portal.roles` and `org_portal.admin_hub` are on in production; without them the Hiring Committee role cannot be adopted. The migration shares nothing with 0068 or 0072. There is no what's-new post: only administrators see anything new, and no congregation has it on. The first customer's Employment page is a separate step for its website's author, after the toggle is on and an opening is published.
