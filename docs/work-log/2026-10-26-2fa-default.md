> **Operator, 2026-10-26 (verbatim):** "2fa should not be required for every one. Is that true?" — then ruled: **"Yes, role-based only"** — new accounts default to not required; the permission / congregation / per-person rules still force it where needed; **existing accounts unchanged**.
> **Finding (orchestrator):** `users.two_factor_required` is `boolean NOT NULL DEFAULT true` (`drizzle/0000_initial.sql:110`, `src/lib/db/schema.ts:34`). The invitation account-creation inserts (`drizzle/0059:1203`, `0064:812`, and the unmerged Community 2b `0065:1937`) all omit the column, so every invited new account is required. `computeEffectiveTwoFactor` (`src/lib/auth/local-login.ts`) ORs the user column with `presby_two_factor_required()` (congregation `organization_settings.require_two_factor` + any granted permission with `requires_two_factor`), then gates on `auth.require_2fa` (on in production). Production (read-only, 2026-10-26): 70 users, 2 with the column true; 0 organizations require 2FA.
