## 0.36.0 — 2026-10-21

### Enhancement: Four fixes from the operator's production review

**Value:** While testing the live platform, the operator noted four places that looked or worked worse than they should. This release fixes all four: the "Sign in with Google" button now looks like Google's own button; the six-digit sign-in code is typed into six separate boxes; every email the platform sends is a properly laid-out message instead of bare text; and the operator's organizations page shows the church structure as a tree that can be searched and filtered. No permission, setting or database change comes with it.

#### What's New

**Google's own sign-in button.** On the sign-in page, "Sign in with Google" is now Google's official button: white with a thin grey border and the four-colour "G" in light mode, near-black in dark mode. A congregation's colours on a branded sign-in page cannot repaint it. It is the one place in the platform allowed to use colours outside the platform's own palette.

**One box per digit for the two-step sign-in code.** After a password, a person with two-step sign-in now sees six boxes. The cursor starts in the first box, each digit moves to the next, Backspace and Delete step back across boxes, and pasting a code (or the phone offering one from a text or an authenticator app) fills all six at once. The code is not sent automatically: the Verify button lights up and Enter submits. **Recovery codes are still accepted** through a "Use a recovery code instead" link under the boxes, which swaps in a single field. The boxes cannot be typed into until the page has fully loaded, so an early tap can no longer send an empty code and count as a failed attempt. The account page where someone first sets up two-step sign-in uses the same boxes, but does not jump the cursor into them.

**Every email is a proper message.** Password resets, email-address changes, feedback and support-ticket notices, statistics-report invitations, custom-domain notices and giving-statement notices now share one layout: a PresbyPortal header, a clear button, the plain link printed underneath it, and a plain-text version for mail programs that prefer one. Along the way:
- Support-ticket and feedback emails used to contain links that went nowhere when clicked from a mail program; they now open the right page.
- A subject such as "Q&A" used to arrive as "Q&amp;A"; subjects now read normally.
- An unusual new email address could previously be shown as formatted text inside the email-change message; it is now always shown as plain text.
- The statistics-report invitation shows its expiry date with "(UTC)" so it no longer depends on the server's clock zone.
- The giving-statement notice still lists no gifts or amounts.
- The fallback sender name now reads "PresbyPortal".

**Organizations as a tree.** Under **Admin > Organizations**, synods, presbyteries and congregations are now shown indented under their parent council, with a count of what sits under each one ("3 congregations") and a badge on any organization that is not active. A search box and type and status filters narrow the list; a match keeps its presbytery and synod above it in grey so it stays in context, and every filter is part of the page address, so a filtered view can be bookmarked. The "Still on default palette" filter still works. If the list cannot be loaded, the page says so and offers to try again. It works at phone width.

#### What changes for people using the platform today

- Anyone with two-step sign-in will see the new boxes the next time they sign in.
- Support staff who receive ticket or feedback emails will find the buttons in them now work.
- Nothing else about signing in changes: the same codes, the same rate limit, the same error messages.

#### What this release does not do, and what you should know

- **Some things have not yet been checked by eye.** The Google button's pressed, disabled and keyboard-focus looks are built but have only been seen in their normal and hover states. Filling the code from a phone's suggestion bar has been tested in a simulated browser, not on a real iPhone or Android phone. The emails have not yet been opened in Gmail or Apple Mail with dark mode on; they ask mail programs to show them in light colours, but some programs may darken them anyway. All three are on the operator's checklist.
- **On some Android keyboards, Backspace in an empty box may not step back** to the previous box (a box with a digit in it still clears). To be checked on a real phone.
- **After a wrong recovery code, the page returns to the six boxes**, and the "Use a recovery code instead" link must be pressed again. The error message points to it.
- **The email button's colour contrast is slightly below the design's own target** (6.84 to 1 against 7 to 1). It is above the platform's accessibility minimum of 4.5 to 1. The operator is choosing between keeping the brand blue and a darker navy.
- **The organizations page shows at most 500 organizations** and says so when there are more; paging is a follow-up for when presbyteries load their full lists. That limit and the "could not load" message have been tested in code but not yet seen in a browser, because the test data has 15 organizations.
- **The "test organization" marker** the operator asked about is not in this release; it needs decisions about what it should change and will be its own piece of work.
- **The sign-in page still shows a developer hint** ("First time? Run `npm run db:seed`") when local login is on; removing it is the operator's call.

#### New Routes

None. Changed pages: `/signin`, `/totp`, `/account/2fa`, `/admin/organizations`.
