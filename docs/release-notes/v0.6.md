## 0.6.0 — 2026-07-02

### Feature: Member Home & Post-Login Routing

**Value:** Sign-in used to dump every user — including members with no admin access — at `/admin`. Users now land at a member home built for them, with navigation that fits their role.

#### What's New

- `/home` member dashboard: greeting, your roles and features, quick links to Account (and Admin, only if you hold `admin.dashboard`)
- Global navigation on member pages with a conditional Admin link and sign-out
- The public landing page no longer hard-links to `/admin`
- Every post-login `callbackUrl` is sanitized through a shared helper; invalid or missing callbacks fall back to `/home`, never `/admin`

---

### Feature: In-App Feedback Wired Into the Dev Loop

**Value:** Member feedback doesn't go to a spreadsheet nobody reads — it interrupts the next coding session, gets triaged into the development pipeline, and closes back to members when it ships.

#### What's New

- Members submit suggestions and bug reports from `/home` (gentle daily prompt with snooze/opt-out) and `/account` (permanent form)
- Admins triage at `/admin/feedback` through a four-state lifecycle (`new → triaged → done / declined`), with email notification on new submissions
- A `SessionStart` hook surfaces the unread count at the start of every Claude Code session — count only, never content (prompt-injection boundary)
- **What's-new** closes the loop user-visibly: admins publish entries at `/admin/whats-new`; members see the latest on `/home` and the full list at `/whats-new`

#### Permissions

| Feature key | Required for |
|-------------|--------------|
| `admin.feedback` | Feedback triage page and status changes |
| `admin.whats_new` | What's-new entry CRUD |

### Feature: Admin Operations Suite

**Value:** The starter's operational state — audit trail, email delivery, account lockouts — was previously visible only via direct database access.

#### What's New

- `/admin/audit` — the full audit log, filterable by action and actor, with IP and user-agent now recorded on every event via a centralized `recordAudit()` helper
- `/admin/email-queue` — queue status at a glance, delivery/open/bounce tracking via a signature-verified Resend webhook, and one-click retry for failed sends
- `/admin/users` shows locked accounts with an audited one-click Unlock

#### Permissions

| Feature key | Required for |
|-------------|--------------|
| `admin.audit` | Audit log viewer |
| `admin.email_queue` | Email queue viewer and retry |

### Feature: Durable Email Delivery

**Value:** A transient Resend failure used to silently drop password-reset and verification emails. Sends are now persist-first with automatic retry.

- Emails enqueue to an `email_queue` table, attempt inline, and retry with exponential backoff via a Vercel cron worker (`CRON_SECRET`-gated)
- A daily maintenance cron sweeps expired reset/verification/pending-2FA tokens
- `EMAIL_DEV_INTERCEPT` / `EMAIL_DEV_REDIRECT_TO` make local and e2e email testing safe

### Security: Hardening Batch

**Background:** Six sibling production apps were mined for the security lessons they learned the hard way.

**Changes:**

- **Per-account login lockout** — 5 failed passwords lock credentials sign-in for 15 minutes (atomic, enumeration-safe, OAuth-exempt); password reset clears the lock
- **Cloudflare Turnstile** — CAPTCHA on sign-in and forgot-password, active only when two env vars are set; verification is endpoint-level, so a direct POST can't bypass a hidden form
- **Auth-mode flags** — `auth.local_login` (go OAuth-only without a redeploy; gates `authorize()` itself) and `auth.require_2fa` (org-wide 2FA master switch); both fail open so a database blip can't lock anyone out
- **Report-only Content-Security-Policy** grounded in what the app actually loads, with a documented fork-tightening path; HSTS `preload` removed (irreversible-domain footgun)
- **`trustHost` fixed** — OAuth no longer hard-fails on non-Vercel production hosts
- **`ACCESS_DENIED` audit telemetry** — admins can finally answer "who tried to reach what and got bounced?"

### Defect Fixes

1. **Email-change verification crashed on click** — `db.transaction()` is unsupported on the neon-http driver; replaced with an atomic `db.batch()`.
2. **Fresh 2FA recovery codes re-displayed on every reload** — a cookie delete ran during Server Component render (forbidden); moved to a client-island-triggered server action.
3. **Every first-time Google sign-in got AccessDenied** — the sign-in check ran before the user row existed; replaced with a provider-aware gate keyed on verified email.
4. **Unique-constraint races returned raw 500s** — Neon nests the Postgres error code under `error.cause`; a shared `isUniqueViolation()` helper plus an atomic upsert eliminated both live races.
5. **Expired email-change claims blocked an address for everyone** — the pending-claim check now ignores expired rows.
6. **2FA-required users with no enrollment were stranded at `/totp`** — they're now carried to enrollment and back through verification to their original destination. Mobile: the account/admin sidebars previously left 140px of content width at 360px; both now stack.

**Testing:**
- [x] 408 unit tests (up from 175), including regression pairs for every defect fix
- [x] 48 end-to-end tests (up from 20) against a live dev server, with cached role sessions, role-boundary coverage, and a production-database isolation guard

### Infrastructure: Developer Loop & Tooling

**Background:** The starter is a teaching artifact; this release hardens the instruction layer as much as the app.

**Changes:**

- `docs/TODO.md` backlog ledger with a same-commit reconciliation rule, session-start read, and pre-push check
- New skills: `/downstream-sync` (contribute fork improvements back upstream), `/test` + `/test-results` (versioned manual QA bank)
- New tripwires: `check:sql-date` (bans the `sql<Date>` type lie on the neon-http driver) and a dependency CVE audit in `/pre-push`
- `docs/ui-standards.md` — UI conventions plus a pre-merge UX audit checklist
- E2E infrastructure: role sessions acquired once via the NextAuth API and cached, so specs stop paying the UI sign-in tax
- Performance: `auth()` and flag reads deduplicated per request (empirically verified — the framework does not do this itself)
- Fifteen new architecture decisions logged (DECISION-014 through DECISION-028)
